# Domain Documentation

This is a single-context repository. Use the root `GLOSSARY.md` for established domain vocabulary and `DECISIONS.md` for decisions whose rationale may help future work.

Create a document under `docs/adr/` only when a consequential, hard-to-reverse, and surprising trade-off warrants a durable architecture decision record. Do not create ADRs for routine implementation choices or duplicate guidance already captured in `AGENTS.md` and the guides under `docs/agents/`.

Use glossary terms consistently. Add or revise a definition only when the domain meaning is established; do not promote proposed features or implementation details into domain concepts.
